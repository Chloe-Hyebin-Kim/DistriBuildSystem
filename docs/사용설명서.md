# DistriBuild 사용설명서

DistriBuild를 처음 받는 사람을 위한 설명서입니다. 저장소나 Python 없이, 받은 폴더만으로 설치하고 쓰는 방법을 적었습니다.

DistriBuild는 언리얼 엔진(UE 4.26, 5.8)의 C++ 빌드를 같은 사내 네트워크의 여러 PC에 나눠서 컴파일합니다. Incredibuild와 비슷한 일을 합니다. 빌드하지 않는 PC는 다른 사람의 빌드를 돕고, 내가 빌드를 시작하면 내 PC는 내 빌드에만 씁니다.


## 1. 보내는 사람: 무엇을 줘야 하나

받는 사람에게 다음 세 가지를 줍니다.

| 줄 것 | 만드는 법 | 주는 방법 |
|---|---|---|
| **패키지 폴더** | 설정 창의 **개발자 PC** 탭 → **헬퍼 PC용 패키지**에서 컴파일러를 고르고 **패키지 만들기**. 고를 컴파일러를 모르면 모두 두세요. | 폴더를 zip으로 묶어 공유 폴더나 USB로 |
| **토큰** | 팀이 함께 쓰는 문자열. 설정 창의 토큰 칸에 넣은 값 | 패키지와 **다른 경로**(메신저, 구두 등)로 |
| **이 설명서** | 패키지 폴더에 `사용설명서.txt`로 들어 있음 | 패키지와 함께 |

패키지에는 토큰이 들어가지 않습니다. 패키지를 만들 때 넣은 컴파일러 덕분에, 받는 PC에 Visual Studio가 없어도 헬퍼 역할을 할 수 있습니다.

받는 사람에게 함께 알려 줄 것입니다.
- 팀이 쓰는 UE 버전(예: 5.8.4)과 Visual Studio 버전
- 사내 네트워크(같은 공유기·같은 층 네트워크 등)에 연결해야 한다는 것
- 그 사람이 직접 UE를 빌드하는지, PC만 빌려주는지

보낼 메시지 예시:

> DistriBuild 패키지를 보냅니다. 압축을 풀고 안에 있는 `사용설명서.txt`를 따라 해 주세요.
> 토큰은 따로 보낼게요. 사내 네트워크에 연결한 상태에서 설치해야 합니다. 설치하려면 관리자 권한이 필요합니다.


## 2. 받는 사람: 시작하기 전에 확인할 것

| 확인할 것 | 필요한 이유 |
|---|---|
| Windows 10 또는 11, 64비트 | 이 프로그램은 Windows 전용입니다 |
| 이 PC의 관리자 권한 | 방화벽을 열고, 자동 시작과 빌드 연결을 설치합니다 |
| 사내 네트워크에 연결됨 | 같은 네트워크의 PC끼리만 서로 찾습니다 |
| Incredibuild가 설치되어 있지 않음 | 둘이 같은 자리를 씁니다. Incredibuild가 있으면 DistriBuild 설치가 중단됩니다 |
| (직접 빌드한다면) UE와 Visual Studio가 설치되어 있음 | 빌드는 평소처럼 Visual Studio로 합니다 |


## 3. 받는 사람: 설치하기 (약 5분)

### 3-1. 폴더 놓기

1. 받은 zip을 메신저나 인터넷으로 받았다면, 압축을 풀기 **전에** zip을 오른쪽 클릭 → **속성** → 아래쪽 **차단 해제**에 체크 → **확인**을 누릅니다. 이렇게 하지 않으면 실행할 때마다 경고가 뜰 수 있습니다.
2. 압축을 **이 PC의 로컬 디스크**에 풉니다. 예: `C:\DistriBuild`
   - 네트워크 드라이브나 USB에서 바로 실행하지 마세요. PC를 켤 때 자동으로 시작하는 에이전트가 그 위치를 보지 못합니다.
   - 나중에 옮기지 않을 곳에 두세요. 옮기면 설정 창에서 다시 등록해야 합니다.
3. 폴더 안에 `DistriBuild.exe`, `agent.json`, `install_client.bat`, `service` 폴더, `msvc` 폴더가 있는지 봅니다. `msvc`는 보낸 사람이 컴파일러를 넣었을 때만 있습니다.

### 3-2. 설정 창 열기

`DistriBuild.exe`를 더블클릭합니다. 검은 창이 잠깐 보였다가 사라지고 설정 창이 열립니다.

- "Windows의 PC 보호" 파란 창이 뜨면 **추가 정보** → **실행**을 누릅니다. 서명하지 않은 사내 프로그램이라 뜨는 경고입니다.
- 백신이 막으면 회사 IT 담당자나 보낸 사람에게 문의하세요. 임의로 백신을 끄지 마세요.

창에는 **개발자 겸 헬퍼**, **헬퍼 PC**, **개발자 PC** 탭이 있습니다. 창 아래쪽 칸에 진행 상황이 나옵니다. 초록색 `[ok]`는 성공, 빨간색 `[!!]`는 문제입니다.

### 3-3. 역할에 맞게 설정하기

**A. 이 PC에서 UE를 빌드한다 (권장: 개발자 겸 헬퍼)**

1. **개발자 겸 헬퍼** 탭을 엽니다.
2. **토큰** 칸에 받은 토큰을 그대로 넣습니다. 앞뒤 공백이 들어가지 않게 주의하세요.
3. **모두 설정 (관리자)**를 누르고, "이 앱이 디바이스를 변경할 수 있도록 허용하시겠어요?" 창에서 **예**를 누릅니다.
4. 상태 세 줄이 모두 초록색이 될 때까지 기다립니다.
   - 개발자: UBT가 DistriBuild로 빌드함
   - 헬퍼: 방화벽 열림
   - 헬퍼: PC를 켜면 에이전트 자동 시작 (실행 중)
5. **Visual Studio를 완전히 닫았다가 다시 엽니다.** 열려 있던 Visual Studio와 터미널은 바뀐 설정을 모릅니다.

**B. 이 PC는 빌려주기만 한다 (헬퍼만)**

1. **헬퍼 PC** 탭을 엽니다.
2. **에이전트 설정**의 **토큰**에 받은 토큰을 넣고 **저장**을 누릅니다.
3. **방화벽 열기 (관리자)**를 누르고 UAC 창에서 **예**를 누릅니다. 빨간 줄이 초록색이 되어야 합니다.
4. **자동 시작 켜기 (관리자)**를 누르고 **예**를 누릅니다. 이제 PC를 켜면 로그인하지 않아도 에이전트가 돕니다.
5. 오른쪽 **이 PC가 제공하는 컴파일러와 엔진** 표에 `msvc-...`로 시작하는 줄이 하나 이상 있으면 됩니다.

이 PC를 쓰는 사람이 느려진다고 느끼면 **동시 작업 수**를 CPU 수보다 낮추고 **저장** → **설정 적용해 다시 시작**을 누릅니다. 에이전트는 원래 낮은 우선순위로 돌아서, 사람이 하는 작업이 먼저 CPU를 씁니다.

### 3-4. 연결됐는지 확인하기 (A를 한 경우)

1. **개발자 PC** 탭을 엽니다.
2. **헬퍼 PC 찾기**를 누릅니다. 표에 팀의 다른 PC가 나옵니다.
   - **상태**가 "연결됨"이고 **맞는 컴파일러**에 값이 있으면 정상입니다.
   - 내 PC는 **구분**이 "이 PC"로 나옵니다. 내 빌드에는 내 PC의 에이전트를 쓰지 않으니 정상입니다.
3. **진단 실행**을 누릅니다. 아래 칸에 `[ok] ... remote slots`가 나오면 준비가 끝났습니다.

다른 PC가 하나도 안 나오면 아래 "5. 문제가 생기면"을 보세요.


## 4. 평소에 쓰기

- **빌드는 평소처럼** Visual Studio나 `Build.bat`으로 합니다. 따로 누를 것은 없습니다.
- 빌드 출력에 이런 줄이 나오면 분산된 것입니다.
  ```
  DistriBuild: 412 actions, 16 local slots, 12 remote slots [BUILD-PC-07(12)]
  ...
  remote: 280   local: 132   skipped/not run: 0
  ```
- **첫 빌드는 오히려 느릴 수 있습니다.** 미리 컴파일한 헤더(PCH, 수 GB)를 다른 PC로 한 번 보내기 때문입니다. 속도는 두 번째 빌드부터 비교하세요.
- **파일 몇 개만 고친 작은 빌드**는 내 PC에서 끝내는 게 빨라서 다른 PC로 보내지 않습니다. 정상입니다.
- **빌드 결과는 혼자 빌드할 때와 같습니다.** 다른 PC에서 실패한 작업은 내 PC에서 다시 컴파일합니다. 빌드 오류가 나면 내 코드의 오류입니다.
- 내가 빌드하는 동안 내 PC는 다른 사람의 새 작업을 받지 않고, 빌드가 끝나면 다시 돕습니다.
- **잠깐 혼자 빌드하고 싶을 때**: 터미널에서 `set DISTRIBUILD_DISABLE=1`(PowerShell은 `$env:DISTRIBUILD_DISABLE=1`)을 실행하고 같은 창에서 빌드합니다. 그 창에서만 적용됩니다.


## 5. 문제가 생기면

| 증상 | 해 볼 것 |
|---|---|
| **헬퍼 PC 찾기**에 다른 PC가 안 나옴 | ① 사내 네트워크에 연결됐는지 봅니다. ② Windows 설정 → 네트워크 및 인터넷 → 연결된 네트워크의 **속성**에서 네트워크 프로필이 **공용**이면 **개인**으로 바꿉니다. 방화벽 규칙은 개인·도메인 네트워크에서만 열립니다. ③ 상대 PC의 방화벽 줄도 초록색인지 확인합니다. ④ 그래도 안 되면 상대 PC가 다른 네트워크 대역에 있는 것입니다. 상대 PC에서 `ipconfig`로 IPv4 주소를 알아내고, 내 PC의 **개발자 PC** 탭 주소 칸에 `192.168.0.21:31890`처럼 넣어 **주소 추가** → **저장**합니다. |
| 상태가 "토큰이 맞지 않음" | 토큰을 다시 받아 정확히 넣습니다. A로 설정했다면 **개발자 겸 헬퍼** 탭에서 다시 **모두 설정**을 누릅니다. |
| 상태가 "연결 실패" | 그 PC가 꺼져 있거나, 에이전트가 안 돌거나, 방화벽이 닫혀 있습니다. 그 PC의 헬퍼 탭에서 방화벽과 자동 시작을 확인합니다. |
| "연결됨 (자기 빌드 중이라 쉼)" | 그 PC 주인이 지금 빌드하는 중입니다. 끝나면 다시 씁니다. 문제가 아닙니다. |
| **맞는 컴파일러**가 비어 있음, 진단에 `0 remote slots` | 내 Visual Studio의 컴파일러 버전이 팀의 다른 PC에 없습니다. 내 PC의 **개발자 PC** 탭 → **헬퍼 PC용 패키지**에서 대상 폴더로 다른 PC의 패키지 폴더(예: `\\그PC이름\c$\DistriBuild`)를 고르고 **패키지 만들기**를 누르면, 그 PC가 1분 안에 내 컴파일러를 씁니다. 그 PC에 쓸 권한이 없으면 보낸 사람에게 부탁하세요. |
| "Incredibuild is installed on this PC" | Incredibuild를 제거한 뒤 다시 **모두 설정**을 누릅니다. |
| 빌드 출력에 `DistriBuild:` 줄이 아예 없음 | ① Visual Studio를 완전히 닫았다 다시 엽니다. ② **개발자 겸 헬퍼** 탭의 첫 줄이 초록색인지 봅니다. ③ UE 5.8에서 작업 수가 적은 빌드는 엔진이 자체 방식(UBA)으로 빌드합니다. 큰 빌드에서 다시 확인하세요. |
| 다른 PC로 거의 안 나감 | **개발자 PC** 탭의 **로컬로 돌린 이유를 빌드 로그에 출력**을 켜고 **저장**한 뒤 다시 빌드하면, 빌드 끝에 이유가 나옵니다. 그 내용을 보낸 사람에게 보여 주세요. |

도움을 요청할 때는 다음을 함께 보내면 빠릅니다.
- 설정 창 아래쪽 칸의 내용 (복사해서 붙여넣기)
- 빌드 출력의 `DistriBuild:`로 시작하는 줄과 끝의 `remote:` 줄
- `%USERPROFILE%\.distribuild\last_build.csv` (마지막 빌드의 작업별 기록)
- 헬퍼 쪽 문제라면 패키지 폴더의 `agent-autostart.log`

토큰은 함께 보내지 마세요.


## 6. 그만 쓸 때

1. 설정 창의 **개발자 겸 헬퍼** 탭에서 **모두 해제 (관리자)**를 누릅니다. 빌드 연결 제거, 방화벽 규칙 제거, 자동 시작 끄기를 한 번에 합니다. B(헬퍼만)로 설정했다면 **헬퍼 PC** 탭의 **자동 시작 끄기 (관리자)**와 방화벽의 **규칙 제거 (관리자)**를 누릅니다.
2. Visual Studio를 다시 엽니다. 이제 평소처럼 혼자 빌드합니다.
3. 패키지 폴더(예: `C:\DistriBuild`)와 `%USERPROFILE%\.distribuild` 폴더를 지웁니다.


## 7. 알아 둘 것

- **사내 네트워크에서만 쓰세요.** 통신은 암호화되지 않습니다. 토큰을 아는 PC만 내 PC에 작업을 보낼 수 있으니 토큰을 꼭 넣고, 외부에 공유하지 마세요. 에이전트는 컴파일러와 셰이더 컴파일러만 실행합니다.
- 다른 사람의 빌드를 돕는 동안 내 PC의 CPU와 네트워크를 씁니다. 에이전트는 낮은 우선순위로 돌지만, 게임 실행이나 녹화처럼 CPU를 많이 쓰는 일을 할 때는 체감될 수 있습니다. 그때는 헬퍼 탭에서 **동시 작업 수**를 낮추세요.
- 나눠 컴파일하는 것은 C++ 컴파일뿐입니다. 링크, 쿠킹, 라이트 빌드는 내 PC에서 합니다.
- 에디터의 셰이더 컴파일 분산은 따로 플러그인 설정이 필요해서 이 설명서에서는 다루지 않습니다. 보낸 사람에게 문의하세요.
- 설정 창으로 바꾼 값은 다음 파일에 저장됩니다. 직접 고칠 필요는 없습니다.
  - 헬퍼 설정: 패키지 폴더의 `agent.json`
  - 개발자 설정: `%USERPROFILE%\.distribuild\client.json`
