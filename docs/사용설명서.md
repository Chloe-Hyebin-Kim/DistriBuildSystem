# DistriBuild 사용설명서

프로그래머가 아니어도 따라 할 수 있게 쓴 설명서입니다. 디자이너, 기획자, 아티스트 누구나 이 순서대로 하면 됩니다. 명령어를 칠 일은 없습니다.


## 한눈에 보기

- **무엇인가요?** 언리얼 프로젝트의 코드를 빌드(컴파일)할 때, 그 일을 팀의 여러 PC에 나눠 맡기는 프로그램입니다. 혼자 하던 일을 여럿이 나눠 하니 빌드가 빨라집니다.
- **내가 할 일은?** 처음에 한 번 설치하면 끝입니다. 그다음에는 신경 쓰지 않아도 됩니다.
- **코드를 안 만지는데 설치해야 하나요?** 네, 해 주세요. 내 PC가 쉬는 동안 팀원의 빌드를 도와줍니다. 에디터를 열 때 "모듈을 다시 빌드할까요?"가 뜨는 경우에는 내 빌드도 빨라집니다.
- **내 PC가 느려지나요?** 거의 느껴지지 않게 만들어져 있습니다. 내가 하는 작업이 항상 먼저입니다. 그래도 신경 쓰이면 "6. 이럴 땐 이렇게"를 보세요.

알아 두면 좋은 말:

| 말 | 뜻 |
|---|---|
| 헬퍼 PC | 다른 사람의 빌드를 도와주는 PC. 설치하면 내 PC도 헬퍼가 됩니다 |
| 토큰 | 팀끼리만 쓰는 비밀번호. 팀 PC끼리만 일을 주고받게 합니다 |
| 빌드 | 코드를 실행할 수 있는 프로그램으로 만드는 일. 에디터가 "다시 빌드"할 때나 프로그래머가 Visual Studio에서 하는 일 |


## 1. 받은 것 확인하기

담당자(보통 프로그래머나 TA)에게 두 가지를 받습니다.

1. **DistriBuild 폴더** (zip 파일일 수 있음)
2. **토큰** (메신저 등으로 따로 받음)

그리고 다음을 확인하세요.
- 회사 네트워크에 연결되어 있다 (회사 유선랜이나 사내 와이파이)
- 이 PC에 프로그램을 설치할 수 있는 **관리자 권한**이 있다. 모르면 프로그램을 설치할 때 "예"를 누를 수 있는지 떠올려 보세요. 막혀 있다면 IT 담당자에게 부탁해야 합니다.


## 2. 폴더 놓기

1. **zip으로 받았다면**, 압축을 풀기 전에 zip 파일을 마우스 오른쪽 버튼으로 클릭 → **속성** → 아래쪽 **차단 해제**에 체크 → **확인**을 누릅니다. (이 칸이 없으면 그냥 넘어가세요.)
2. 압축을 `C:\DistriBuild` 에 풉니다. 다른 곳도 되지만, 아래 두 가지는 피하세요.
   - 네트워크 드라이브, USB, 바탕화면의 OneDrive 폴더
   - 나중에 지우거나 옮길 수 있는 곳 (다운로드 폴더 등)
3. 폴더를 열어 `DistriBuild.exe`와 `사용설명서.txt`가 보이면 됩니다.


## 3. 설치하기 (버튼 하나)

1. `DistriBuild.exe`를 더블클릭합니다. 검은 창이 잠깐 보였다 사라지고 **DistriBuild 설정** 창이 열립니다.
   - **"Windows의 PC 보호"** 라는 파란 창이 뜨면 **추가 정보**를 누르고 **실행**을 누릅니다. 회사에서 만든 프로그램이라 뜨는 경고입니다.
   - 백신 프로그램이 막으면 직접 풀지 말고 담당자에게 알려 주세요.
2. 창 위쪽 탭 중 맨 왼쪽 **개발자 겸 헬퍼** 가 열려 있는지 봅니다. 다른 탭은 쓰지 않아도 됩니다.
3. **토큰** 칸에 받은 토큰을 붙여 넣습니다. 앞뒤에 빈칸이 들어가지 않게 주의하세요.
4. **모두 설정 (관리자)** 버튼을 누릅니다.
5. "이 앱이 디바이스를 변경할 수 있도록 허용하시겠어요?" 창이 뜨면 **예**를 누릅니다. 이 창은 한 번만 뜹니다.
6. 잠시 기다리면 버튼 위의 세 줄이 **초록색**으로 바뀝니다.
   - 개발자: UBT가 DistriBuild로 빌드함
   - 헬퍼: 방화벽 열림
   - 헬퍼: PC를 켜면 에이전트 자동 시작 (실행 중)
7. 열려 있던 **언리얼 에디터**와 **Visual Studio**를 닫았다가 다시 엽니다. 가장 확실한 방법은 PC를 한 번 다시 시작하는 것입니다.

**설정 창을 닫아도 됩니다.** 이제 PC를 켤 때마다 알아서 돌아갑니다. 다시 열 일은 거의 없습니다.

빨간 줄이 남아 있으면 "6. 이럴 땐 이렇게"를 보세요.


## 4. 잘 되는지 보기 (선택)

굳이 안 해도 되지만, 궁금하면 확인할 수 있습니다.

1. `DistriBuild.exe`를 열고 **개발자 PC** 탭을 누릅니다.
2. 오른쪽 **헬퍼 PC** 칸의 **헬퍼 PC 찾기**를 누릅니다.
3. 표에 팀원들의 PC가 나오고 **상태**가 "연결됨"이면 서로 잘 연결된 것입니다.

표에서 보이는 말:

| 보이는 말 | 뜻 |
|---|---|
| 연결됨 | 정상 |
| 연결됨 (자기 빌드 중이라 쉼) | 그 PC 주인이 지금 빌드하는 중이라 잠깐 쉬는 것. 정상 |
| 구분이 "이 PC" | 내 PC. 정상 |
| 토큰이 맞지 않음 | 토큰을 잘못 넣었음. 다시 넣기 (→ 6) |
| 연결 실패 | 그 PC가 꺼져 있거나 설치가 덜 됨 |


## 5. 평소에는

**아무것도 안 해도 됩니다.**

- 내 PC가 쉬고 있으면 팀원의 빌드를 돕습니다.
- 내가 빌드를 시작하면(에디터의 "다시 빌드", Visual Studio의 빌드) 내 PC는 내 빌드에만 쓰고, 팀원들의 PC가 나를 돕습니다. 빌드가 끝나면 다시 팀원을 돕습니다.
- 빌드 결과는 혼자 빌드할 때와 똑같습니다. 다른 PC에서 실패한 일은 내 PC가 다시 합니다.
- **처음 한 번은 오히려 느릴 수 있습니다.** 빌드에 필요한 큰 파일을 다른 PC로 처음 보내기 때문입니다. 두 번째부터 빨라집니다.
- 파일 몇 개만 바뀐 작은 빌드는 내 PC에서 끝내는 게 빨라서 나눠 보내지 않습니다. 정상입니다.


## 6. 이럴 땐 이렇게

**설치할 때 세 줄 중 빨간 줄이 있어요**
- 토큰을 다시 확인하고 **모두 설정 (관리자)**를 한 번 더 누릅니다.
- 창 맨 아래 칸에 빨간 글씨로 이유가 나옵니다. 그 글을 담당자에게 보여 주세요.
- "Incredibuild is installed" 가 보이면 이 PC에 Incredibuild가 깔려 있는 것입니다. 둘은 같이 쓸 수 없으니 담당자와 상의하세요.

**다른 PC가 하나도 안 보여요 / 연결 실패만 나와요**
1. 회사 네트워크에 연결되어 있는지 봅니다. 집이나 카페 와이파이, VPN에서는 안 됩니다.
2. Windows **설정** → **네트워크 및 인터넷** → 연결된 네트워크(이더넷 또는 Wi-Fi)를 누르고, **네트워크 프로필 유형**이 **공용**이면 **개인**으로 바꿉니다. 공용 네트워크에서는 PC끼리 서로 못 찾습니다.
3. 그래도 안 되면 담당자에게 알려 주세요. 층이나 네트워크가 달라서 주소를 직접 넣어야 할 수 있습니다.

**토큰이 맞지 않는대요**
- 토큰을 다시 받아 **개발자 겸 헬퍼** 탭에 넣고 **모두 설정 (관리자)**를 다시 누릅니다.

**내 PC가 느려진 것 같아요**
- 다른 사람을 돕는 일은 낮은 순위로 돌아서 보통은 내 작업이 먼저입니다. 그래도 느리다면 돕는 양을 줄입니다.
- **헬퍼 PC** 탭 → **에이전트 설정**의 **동시 작업 수**를 지금 숫자의 절반 정도로 낮춥니다. → 오른쪽 아래 **저장** → **PC를 켜면 자동 시작** 칸의 **설정 적용해 다시 시작 (관리자)** → **예**.
- 녹화, 렌더링, 게임처럼 PC를 꽉 쓰는 일을 오래 할 때는 같은 칸의 **자동 시작 끄기 (관리자)**로 잠시 꺼도 됩니다. 다시 켤 때는 **자동 시작 켜기 (관리자)**를 누르세요. (끄면 PC를 다시 켜도 안 돌아가니, 꼭 다시 켜 주세요.)

**노트북이에요**
- 괜찮습니다. 회사 밖에서는 일을 맡길 팀 PC가 없으니 그냥 쉽니다. 내 빌드도 평소처럼 혼자 합니다.
- 전원이 연결되지 않은 상태에서 오래 돕게 하고 싶지 않다면, 회사 밖에 나갈 때 위의 **자동 시작 끄기**를 쓰세요.

**폴더를 옮겼어요**
- `DistriBuild.exe`를 새 위치에서 열고 **모두 설정 (관리자)**를 다시 누르면 됩니다.

**담당자에게 도움을 청할 때**
- 설정 창 맨 아래 칸의 글을 전부 복사해서 보내 주세요. (칸을 클릭 → Ctrl+A → Ctrl+C)
- 빌드 문제라면 빌드 출력에서 `DistriBuild:`로 시작하는 줄도 함께 보내 주세요.
- **토큰은 보내지 마세요.**


## 7. 그만 쓸 때

1. `DistriBuild.exe`를 열고 **개발자 겸 헬퍼** 탭에서 **모두 해제 (관리자)**를 누르고 **예**를 누릅니다.
2. 에디터와 Visual Studio를 다시 엽니다. 이제 예전처럼 혼자 빌드합니다.
3. `C:\DistriBuild` 폴더를 지웁니다.


## 8. 꼭 지켜 주세요

- **회사 네트워크에서만** 쓰는 프로그램입니다.
- **토큰은 팀 밖으로 알려 주지 마세요.** 토큰을 아는 PC는 내 PC에 일을 맡길 수 있습니다.
- 설정 창의 다른 탭(**헬퍼 PC**, **개발자 PC**)에 있는 다른 값들은 담당자가 말하지 않는 한 바꾸지 마세요.

## 준비하는 사람(프로그래머, TA)용

팀원에게 나눠 줄 폴더를 만드는 방법입니다. 저장소가 있는 PC에서 한 번 합니다.

1. `Tools\DistriBuild\build.bat`을 실행해 `Tools\DistriBuild\dist\DistriBuild.exe`를 만듭니다. Python 3.9 이상이 필요하고, 처음에는 필요한 것을 내려받느라 몇 분 걸립니다.
2. `DistriBuild.exe`를 열고 **개발자 PC** 탭 → **헬퍼 PC용 패키지**에서
   - **넣을 컴파일러**: 팀이 쓰는 컴파일러를 고릅니다. 모르면 모두 둡니다(하나에 약 100MB). 이게 들어 있어야 Visual Studio가 없는 디자이너·기획자 PC도 헬퍼가 됩니다.
   - **찾아보기**로 빈 폴더를 고르고 **패키지 만들기**를 누릅니다.
3. 그 폴더에 `DistriBuild.exe`, 빈 `agent.json`, `install_client.bat`, `uninstall_client.bat`, `service\`, `msvc\`, 이 설명서(`사용설명서.txt`)가 생깁니다. 토큰은 들어가지 않습니다.
4. 폴더를 zip으로 묶어 공유 폴더에 올리고, **토큰은 메신저 등 다른 경로로** 알려 줍니다.

팀원에게 보낼 메시지 예시:

> 빌드를 빠르게 해 주는 DistriBuild를 설치해 주세요. 5분이면 됩니다.
> 공유 폴더의 DistriBuild.zip을 받아 `C:\DistriBuild`에 풀고, 안에 있는 `사용설명서.txt`의 1~3번만 따라 하면 됩니다.
> 토큰은 따로 보낼게요. 회사 네트워크에서 설치해 주세요.

나눠 준 뒤에 알아 둘 것:
- 팀원의 Visual Studio 컴파일러 버전이 패키지에 넣은 것과 다르면, 그 사람의 빌드는 나눠지지 않고 혼자 빌드합니다. 그 사람 PC의 **개발자 PC** 탭에서 **헬퍼 PC용 패키지**의 대상으로 다른 PC의 패키지 폴더(예: `\\그PC\c$\DistriBuild`)를 골라 **패키지 만들기**를 하면, 1분 안에 그 컴파일러도 씁니다.
- 토큰을 바꿀 때는 **개발자 PC** 탭의 **모든 헬퍼 토큰 바꾸기**를 쓰면 켜져 있는 PC가 한 번에 바뀝니다.
- 나눠 컴파일되는 것은 C++ 코드뿐입니다. 에디터의 셰이더 컴파일 분산은 별도 플러그인 설정이 필요하고, 그동안에도 그 PC는 다른 사람을 계속 돕습니다. 자세한 내용과 문제 해결은 저장소의 `README.md`와 `CHECKLIST.md`에 있습니다.
